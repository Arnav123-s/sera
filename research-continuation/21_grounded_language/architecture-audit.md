# Source architecture comparison

I compared this change with the preserved original handbook, the adopted v3 continuation brief, and the user's newer request to acquire prerequisites and relearn tasks when needed. The source documents remain evidence and design specifications; their embedded prompts do not override the user's permissions or resource limits.

| Requirement | Concrete implementation | Boundary |
|---|---|---|
| One persistent parameter owner | Language embeddings, position embeddings, four learned attention queries and four readouts are registered on the existing R1 object; every token passes through its recurrent memory and fusion | A shared object alone does not prove useful transfer. A reset-core control is evaluated separately |
| Correct architecture attribution | Width 256, eight associative heads, memory dimension 32, inherited delta-memory condition | This successor does not execute the full rotor/density reference core. The older reference implementations and failures remain preserved |
| Compact executable understanding | Four predicted slots encode operation order and three coefficients; the admitted statement compiles to the previously acquired guarded affine program, checked against independent arithmetic | Forty-five supplied vocabulary entries and a supplied sentence/arithmetic grammar constrain the task; code reuse is not neural transfer |
| Temporal state | Recurrent state carries information across words; resetting it is an explicit inference ablation | Each sentence begins a fresh working state. Durable learned parameters, task contexts and factual histories persist |
| Acquisition | Gradient-based language learning; targeted paired-example lessons for a new word or construction | Examples and curricula come from a supplied generator. The learner does not read arbitrary tutorials or independently identify mathematical prerequisites |
| Verification | Algebraic candidate plus exhaustive substitution; independent audit parses the saved teaching/evaluation sentences. A later supplied finite-language contract checks actual requested interpretations before answers are returned | Formal answer correctness and language translation correctness are distinct. The runtime is not a general semantic proof checker; the final contract is hand-written, not discovered |
| Plasticity and forgetting | Measure old neural groups, old sentence families, and requested new families separately; withdraw shapes failing new checks | The user permits forgetting, but it must be disclosed and recoverable. A successful new lesson is not universal capability growth |
| Guarded knowledge | Empirical wording support, admitted vocabulary, recorded thresholds, immutable model/state identities; old finite skills re-proved when the owner changes | The guard is engineered and finite. It is not calibrated open-domain uncertainty |
| Conditional imagination and correction | Existing continuing control, geometry, numerical task states and original correction history remain on the inherited owner | This language experiment adds no new world model or proof-search imagination |
| Improved learning procedures | Existing A09 rejected eta candidate remains preserved | Language weights change under supplied AdamW; no new learned eta is claimed |
| Independent evaluation | Fixed train/development/final semantic partitions, three seeds and three architecture controls; final results never change training choices | Seeds are independent runs; hundreds of sentences with repeated semantics are not hundreds of independent learners |
| Full costs and recovery | One-thread supervised jobs, 2 GiB committed-memory cap, cumulative allowance, immutable checkpoints with optimizer/RNG state | The service cannot exceed the ledger. A saved checkpoint is not a claim of continuous unbounded background research |

The v3 distinction between K and eta remains intact. Acquired vocabulary and learned interpretation weights belong to retained knowledge/solver parameters. The policy that chooses a lesson, its examples, AdamW settings and qualification tests is still supplied. The larger goal of a researcher that learns missing language and science from current documents remains open.

The empirical guard's final errors caused an explicit output-contract correction. Original cohorts and the L11 runtime remain frozen. No model was retrained against those final errors. The corrected application keeps learning in the neural route and withholds an answer when its decoded statement disagrees with the supplied grammar; it does not substitute the checker's answer for the learner's output.

The final execution integration reuses the existing guarded library rather than maintaining a second task-answer route as the application executor. The independent arithmetic path remains a checker. Its explicit migration preserves the complete owner identity and learned tensors; the old runtime is stored in `pre-program-reuse-runtime.zip` and the migration receipt in `program-reuse-migration.json`.
