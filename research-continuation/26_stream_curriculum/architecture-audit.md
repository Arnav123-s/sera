# Architecture alignment and teaching scope

I compared this implementation with the original editable handbook and the v10
continuation, especially C01, C02, C07, C09 and C11. The earlier v5–v10 packet
verification remains in release 25; this cycle does not restart it. The original
handbook is pinned at `2371a18a074680d147f1f43cb7ffca2c0970d3dc2a08bccc095c1f71a688b528`.
The user subsequently prioritized real-data teaching before capability verdicts.
This release advances that language-acquisition dependency with actual training.

| Contract | Concrete implementation and evidence |
|---|---|
| One numerical owner | `StreamR1.attach` extends the restored `ConstraintR1` in place. The numerical, typed, solver, inquiry and new request references share that object. `integration.json` records the selected checkpoint's aliases and restore. Independent experimental descendants are labelled controls; the selected descendant is the usable request learner. |
| Learned language | 11,514 source training requests teach an embedding, input projection, normalization, intent head and BIO entity head. The shared route calls the existing R1 recurrent operation for each valid token. A pooled route receives the same examples and update budget. |
| Grounding and provenance | The original publisher's annotated requests supply text/category supervision. The 60 intent meanings, 55 entity categories, split roles and annotation syntax are supplied. All source identities and CC BY attribution are retained. Desired requests remain distinct from observed events. |
| Persistent plastic weights | Adam updates 450,219 new parameters. Exact weights, Adam moments, torch RNG, source byte cursor, buffered rows and stream RNG are checkpointed. The six-block experiment carries the same learned weights and optimizer forward; replay memory persists. |
| Conditional imagination | The predecessor's learned role binding, acquired dynamics and continuous conditional search remain available on the same owner. A prior motion request is checked after attachment. New MASSIVE intent/entity predictions are exposed as request annotations, not silently translated into physical constraints or factual observations. |
| Retained earlier behavior | Every completed fit checks 145 unchanged predecessor tensors and 96 exactly retained earlier language outputs. The legacy applicability gate and immutable stores retain their original identities. The domain-stage matrices separately measure retention in the new, changing interface. |
| Finite compact knowledge | New parameters store a learned mapping; 256 retained examples support replay. Full source bytes, unique-ID bookkeeping, optimizer state and historical checkpoints are charged separately. The small replay count is not the system's entire storage cost. |
| Independent assessment | Protocols precede their fits; development selects a fixed checkpoint; one official test cohort evaluates all fixed candidates. Independent counting reconstructs intent, spans and frames from saved predictions. |

The fast request operation propagates token state and emits a frame. It does not
perform the predecessor's continuous imagined-control settling on each request.
Supervised optimization changes new weights. Replay changes training exposure.
These operations keep the handbook's state-time, weight-learning and investigator
time scales distinct. The fixed Adam update, curriculum, retrieval and replay
policy are engineering contributions; the fitted text-to-frame mapping is learned
by SERA. The six domain blocks test successive acquisition within NLU. Their
results define the measured scope without extrapolating to every task family.

Shared ownership is verified structurally. The separately trained recurrent and
pooled controls measure its task-specific effect; neither object identity nor
the existence of a derivative is used as evidence of positive cross-task transfer.
The old core is protected in this experiment. Future shared-core updates need an
explicit acquisition/retention intervention rather than an ownership argument.

The circle and probability-cloud ideas remain preserved in their labelled prior
studies. This release adds a data-trained language interface to that lineage; it
does not rename request classification as a new quantum mechanism. Testing
Equilibrium Propagation, correlated Born banks or learned investigation remains
separate work under the original cookbook. A language request annotation is useful
as a file-processing result; enabling downstream actions requires a tested
semantic bridge and the existing action/evidence contracts.

The next architectural connection is source-qualified request entities to a
persistent task's dependencies, followed by verified execution, correction and
reacquisition on a new frozen task stream. The existing official test is now
reserved solely for the declared measurement and must not become a tuning set.
