This continuation teaches a registered investigation policy to choose useful evidence for a missing acceleration response. The continuing R1 owner keeps a joint mechanism cloud, imagines consistent motion branches with its learned integral operator, acquires the selected practice observation and rewards progress against a separate check. Its policy weights, optimizer, random generator, original goals and evidence receipts persist across sessions.

## Run a continuing practice task

In the prepared workspace, choose a new output directory for each invocation:

```powershell
.venv/Scripts/python.exe scripts/run_completion_bounded.py --seconds 60 --output runs/my-completion-001 --module experiments.verified_completion.runtime -- practice --id my-response-1 --seed 32510
.venv/Scripts/python.exe scripts/run_completion_bounded.py --seconds 40 --output runs/my-completion-status-001 --module experiments.verified_completion.runtime -- status
```

`practice` explicitly selects the qualified learned policy. A seed identifies a reproducible conditional environment; it is recorded with every receipt. Reusing the same task identifier resumes its committed stages. Repeating a completed task returns its saved result without another reward. A new environment needs a new identifier and seed. The default live store is `runs/sera-completion-live`; the earlier `runs/sera-grounded-live` remains preserved and supplies its original task history.

The result includes the initial and revised joint cloud, four imagined branches, the chosen investigation, independently calculated reward and updated policy identity. Each branch retains one sampled mechanism across both time points. Motion uses a declared acceleration grid of 1/60 with at most 1/120 projection error; the probability cloud and reward use the unrounded values.

For a recommendation from the strongest measured default:

```powershell
.venv/Scripts/python.exe scripts/run_completion_bounded.py --seconds 60 --output runs/my-recommendation-001 --module experiments.verified_completion.runtime -- recommend --id my-response-2 --seed 32511
```

The default remains goal-information selection, as decided by the frozen comparison. A recommendation alone performs no credit update. `status` reports the continuing owner, checked updates and retained tasks.

## Scope and evidence

This interface is labeled `MODEL_CONDITIONAL_PRACTICE`: the response family, uncertainty features, observation costs and checker are supplied. What SERA learns here is its evidence-selection policy. Acquisition adjusts registered joint completion weights; checked reward adjusts selection weights. Imagined branches add zero factual observations. Human-authored language and physical definitions remain in the retained predecessor.

The source interface accepts the qualified local practice provider. arXiv source research remains available through the retained grounded reader and preserves source identities. The original momentum goal remains open with its prior references and existing admission rules.

## Restore and inspect

After the predecessor fixtures described in [repository setup](../../docs/REPOSITORY_MAP.md#setup-and-verification):

```powershell
.venv/Scripts/python.exe scripts/completion_artifacts.py --restore
```

This restores the selected checkpoint and verifies the published bytes. Add `--research` to restore both candidates, exact intermediate checkpoints, optimizer/RNG state, traces, all final cases and the audit session. Divergent local files are refused, never replaced. Training and final evaluation commands refuse to overwrite completed studies.

The live resource balance is in `runs/v3-batch-001/budget.json`; a published historical balance is not a new allowance. Runtime invocations use the existing one-thread, 2 GiB process-tree supervisor.
