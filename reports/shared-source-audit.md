# SERA 0.5 comparison with the original source packet

I returned to the original archive, its editable handbook, and `source/R1.dot`, `source/R2.dot` and `source/system.dot`. The central implementation change is a common learned R1 owner. World prediction, typed inference and legacy sequence inference now update and read the same memory parameters. Earlier separate-model studies remain preserved.

This is a bounded implementation of the handbook's first integration direction. It does not establish that every recipe or architecture family is complete. The [measured report](shared-learner-study.md) distinguishes learning, transfer, retention and deployment outcomes. The [frozen protocol](../research/shared-learner-protocol.md) defines the budgets and controls before the main results.

## Disposition of the preceding audit

D01's separate-parameter defect is repaired in the new shared variants; it remains an accurate description of the preserved historical models. D03 and D04 retain the 0.4 repairs, with additional instructed-binding and calibration checks. D09 gains a tested shared-owner adapter migration. D10 gains an equal-update/equal-example shared-core comparison, while exact compute matching and independently trained rank sweeps remain open. D15's preservation requirement continues through immutable files, explicit run roles and exact old Git blobs.

D02, D05, D06, D08, D11, D12 and D13 remain research limitations: evolving improvement procedures, learned sequential diagnosis, learned representations, general program abstraction, uncertainty-aware planning, external evaluator isolation, and sustained improvement per full cost. D07's narrower discovery interface and extra determinism checks remain documented. D14's original source reproductions stay available in the previous audit; this release does not relabel them as new runs.

The behavioral checklist is completed only against the actual outcomes in the performance report. A successful structural repair does not turn a rejected learning candidate into an admitted capability.

## Repairs found during full execution

The first full reference trials failed even though a short development run passed. The repaired workspace freezes the SVD-selected right-singular subspace during each backward pass, while retaining spectral rank truncation in the forward computation. Gate clamping avoids saturated square-root derivatives. This is a declared gradient approximation; it is not an exact spectral derivative. [PyTorch documents the instability of singular-vector gradients near repeated or small singular values](https://docs.pytorch.org/docs/stable/generated/torch.linalg.svd.html). The earlier spectral-gradient implementation and failures remain recoverable at the original source commit.

Full updating and replay also damaged old capabilities in the first complete delta cohort. The scoped adapter was added as a response, using new evaluation cases. I therefore label the repaired experiment as a follow-up and retain the initial results and costs. The R2 assembly found another executable defect: wrapping a valid stored macro could exceed the interpreter depth bound. Candidate enumeration now rejects that wrapped body before environment execution, within the existing enumeration cap. The parent library and its valid programs remain intact.
