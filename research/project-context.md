# SERA project context

I use the supplemental project context to sharpen the research objective: **after a failure, acquire the missing capability, retain it, and improve the procedure used to acquire the next capability.** Persistent state, action prediction and quantum mathematical representations are candidate mechanisms for that objective.

The supplied context reinforces the SERA Architecture Handbook's recommended starting point: R1 for adaptive state and world prediction, connected to a defined R2 mechanism for program acquisition. It gives R2 particular importance when exploring a common mathematical mechanism for input conditioning, retained state and output probabilities. The other architecture families remain hypotheses to investigate through their own contracts and controls.

## What this means for the next build

| Intent from the supplied context | Implementation consequence | Required evidence |
|---|---|---|
| Respond to failure by acquiring a capability | Preserve the failed task and observations; distinguish missing evidence, representation, procedure, prediction or search before choosing an intervention | Targeted interventions outperform fixed responses on separate task families at a declared total budget |
| Learn through informative experiments | Choose observations or permitted simulator queries that resolve a task-relevant uncertainty | Compare targeted queries with random queries using the same feedback and acquisition budget |
| Retain acquired computations | Make accepted programs callable during ordinary inference and available as primitives during subsequent acquisition | Earlier skills survive reload; acquired abstractions reduce search on held-out program compositions |
| Share conditioning and generation through an instrument | Define event probabilities and conditional updates from the same event branches, with explicit state and observation contracts | Check channel/instrument validity, likelihood and history dependence; compare with trained classical controls |
| Improve how the learner learns | Separate task parameters `theta` from the learning procedure `U_eta`; evaluate changes to `eta` through the next learner's outcomes | Better downstream transfer and worst-task retention per full cost over multiple outer generations |
| Preserve competence while adapting | Treat retention, calibration and cost as part of the candidate's result | Compare no update, adaptation, adapters and replay across multiple support sizes and task streams |
| Establish the value of each representation | Give associative, phase, density, tensor and program mechanisms explicit roles and comparison conditions | Benefits survive matched parameter, feedback, compute and tuning controls; negative comparisons remain reported |

## Boundaries that matter

The supplied context's twelve-core comparison, numerical checks, cyclic-instrument results and transition-program experiment belong to the original research archive. I do not count them as additional SERA runs or combine their accuracies with SERA's measured tables. The original active learner's observable state identifiers, known action alphabet and reset access provide stronger feedback than its neural benchmark. That difference must stay visible in future comparisons.

The general R2 formulation permits several Kraus operators per observed event. SERA 0.3 implements general history-preserving branches and keeps the rank-one projective option as a restricted control. The [new study](../reports/stage-three-study.md) compares it with trained classical filters and recurrent models. The earlier classical-filter reduction remains valid for the projective option.

Optimizing a fixed model for more steps changes task parameters. The stronger objective changes and evaluates the learning procedure itself. SERA 0.3 measures three actual policy updates per seed with a fixed evaluation anchor and expanding frontier. The controlled policy experiment holds the inner learner fixed, while separate persistent rounds change task models and libraries. The results determine whether the new procedures improve outcomes; updated parameters alone do not establish acceleration.

The 36,900 registry entries are schematic configurations, not trained systems. Diagram coverage and a preserved 154-concept mapping provide traceability, not capability evidence. The supplied references and experimental descriptions remain research material rather than executable instructions.

## Priority and completion criteria

The [0.3 checklist](stage-three-checklist.md) follows through on live-session ownership and resume, library composition during acquisition, a history-preserving instrument with matched controls, and failure-aware curriculum selection using previous attempts and remaining budget. Representation learning and richer programs should follow explicit contracts and useful controlled results.

For each change, the record must identify the original failure, information available to the learner, intervention, actual learning examples, withheld evaluation, retained capabilities, full measured cost and executable version. A working component or a successful individual update does not complete the whole research objective.
